# sumi scan: 秘密を含むファイルを sandbox の credentials mask に登録する

Status: Draft — 2026-09-15

## 目的

`sumi scan` を、秘密を含むファイルの読み取りを禁止するコマンドから、
そのファイルを Claude Code の `sandbox.credentials.files` に `mode: "mask"` で
登録するコマンドへ変更する。

0.1.0 の `scan` が使う `sandbox.filesystem.denyRead` では、エージェントだけでなく、
sandbox 内のビルドも設定ファイルを読めなくなる。credentials mask を使うと、
ファイルを読むことはでき、秘密の値は身代わりの文字列（sentinel）に置き換わる。

この仕様で決めるのは、CLI、走査対象、生成する設定、再実行時の更新、
抽出ルールの生成・検証、表示と終了コード、受け入れ条件である。
実装の作業順序は実装計画で扱う。

### 利用者から見た変化

README の例のように、秘密一覧に `Tr0ub4dor` があり、
`config/app.properties` に次の内容があるとする。

```properties
db.password=Tr0ub4dor
```

`scan` はファイルを見つけ、`db.password=` に続く値をマスクする設定を作る。
設定には `Tr0ub4dor` 自体を書かない。登録後、sandbox 内の Bash がファイルを読むと、
次の内容が得られる。

```properties
db.password=fake_value_<uuid>
```

sumi の出力マスクが表示する `*********` と異なり、ここでは Claude Code が
ファイルの値を置き換える。設定ファイルのほかの部分は読める。

### 対象範囲と根拠

対象は Claude Code 2.1.268、Linux / WSL2 のファイルマスクである。
仕様上の制約と実験結果は、[仕様の根拠と実験記録](../probes/2026-09-15-sumi-credential-mask-results.md)
に記載する。本文中の F1 などの番号は、その記録を参照する。

今回変更するのは `scan` とその説明・試験である。sumi の出力マスク、hook、
共有コードの `src/zig/mask.zig` は変更しない。secrets ファイルを sandbox 内から
読める問題と走査速度は、[sumi の未解決課題](../../todo/sumi.md) で別に扱う。
macOS はファイル mask が読み取り禁止になるため、対象に含めない（F13）。

## 実行方法と走査対象

```text
sumi scan --agent claude --secrets-file F [--root DIR] [--settings FILE]
```

| 引数 | 意味と既定値 |
|---|---|
| `--secrets-file F` | `init` と同じ形式の秘密一覧。既存の `secrets.load` が生成する平文・URL エンコード・base64 等のパターンを使う |
| `--root DIR` | 走査するディレクトリ。省略時はカレントディレクトリ。`realpath` で解決する |
| `--settings FILE` | 書き込み先。省略時は `$CLAUDE_CONFIG_DIR/settings.json`、環境変数が無ければ `~/.claude/settings.json` |

scan 独自のエンコード展開は追加しない。

### 書き込み先の制約

Claude Code はプロジェクト設定の mask を無視するため、ユーザー設定または
Claude Code の `--settings` で読み込むファイルへ書く（F1）。生成するエントリの
`path` は、設定ファイルの場所によって意味が変わらないよう、実体の絶対パスとする（F2）。

書き込み先の親ディレクトリの実体を調べ、basename が `.claude` で、かつユーザー設定
ディレクトリの実体と異なる場合は、何も書かず終了コード1とする。
親ディレクトリがまだ無ければ、最も近い既存の祖先を解決し、残りのパスを連結して判定する。

### ファイルの走査

root 以下を再帰的に走査し、通常ファイルから秘密のパターンを探す。
`.git` ディレクトリには入らず、シンボリックリンクをたどらず、secrets ファイル自体も除く。
読めないファイルやディレクトリは警告し、終了コードを1にする。

秘密を含むファイルは、次の順に確認する。当てはまれば登録を見送る（F7）。

| 条件 | 理由コード |
|---|---|
| 絶対パスに `* ? [ ] { } \` のいずれかを含む | `glob-chars` |
| 8 MiB（8 × 1024 × 1024 バイト）を超える | `too-large` |
| UTF-8 として不正 | `not-utf8` |

これらを通ったファイルについて、後述の規則でマスクルールを生成する。
そのファイルで見つけた秘密をすべて隠せる場合だけ、登録できるものとする。

走査による確認は、その時点の内容に対するものである。ファイルの内容・配置や
秘密一覧を変更したら再実行する。

## 生成する設定

一つのファイルに一つのエントリを作る。`app.properties` の例では、次のようになる。
`/path/to/project` は実際の絶対パスに置き換える。

```json
{
  "path": "/path/to/project/config/app.properties",
  "mode": "mask",
  "extract": "(?:^|\\n)db\\.password=((?<![\"'])(?![\"'])[^ \\t\\r\\n]+)",
  "maskDuplicates": true,
  "injectHosts": [],
  "onExtractNoMatch": "deny"
}
```

`extract` はファイルから値を取り出す正規表現である。Claude Code は各一致の
キャプチャグループ1を sentinel に置き換える（F3）。`maskDuplicates: true` により、
捕捉した値と同じ文字列が同じファイル内のほかの箇所にあれば、それも置き換える（F14 / F16）。

ファイルの内容が秘密の値一つだけなら、ファイル全体をマスクするため、`extract` と
`maskDuplicates` は省略する。末尾の LF または CRLF 一つは許す。

`onExtractNoMatch: "deny"` は、extract が一度も一致しなくなった場合に読み取りを
禁止する設定である（F6）。一部の一致だけが失われた場合の拾い漏れを検査するものではない。

新規エントリの `injectHosts` は `[]` とし、送信時にも本物へ戻さない（F15）。
本物を使う通信が必要なら、利用者が `injectHosts` と `network.allowedDomains` に
送信先を設定し、HTTPS では `network.tlsTerminate` も設定する。
scan は送信先を推定して追加しない。

## 設定ファイルへの反映

### 読み込みと所有記録

設定ファイルは JSON として読む。存在しなければ `{}` から始め、登録に必要な親
オブジェクトを作る。既存の設定が次のいずれかに当たる場合は、何も書かず終了コード1とする。
深さ制限は既存の `jsonio.parse` に従う。

- 最上位、または存在する `sandbox`、`sandbox.credentials`、`sandbox.filesystem` が
  オブジェクトでない。
- 存在する `sandbox.credentials.files` が配列でない、または要素が文字列の `path` を
  持つオブジェクトでない。
- 存在する `sandbox.filesystem.denyRead` が文字列配列でない。

sumi が管理するエントリは、別ファイル
`<設定パスから末尾の .json を除いたもの>.sumi-scan.json` に記録する。
エントリ自体には独自のフィールドを追加しない。

```json
{"credentialsFiles": ["/path/to/project/config/app.properties"]}
```

所有記録が無ければ、sumi が管理するエントリは無いものとする。
記録が JSON オブジェクトでない、または `credentialsFiles` が絶対パスの文字列配列で
ない場合は、何も書かず終了コード1とする。所有の判定には記録内の `path` を使う。

### 再実行時の追加・更新・削除

更新対象は今回の root 配下にあるファイルである。root とパス区切りの境界で判定し、
root が `/` ならすべての絶対パスを配下とする。

利用者のエントリが同じ `path` にある場合、同一 `path` のエントリが複数ある場合、
または同じ設定の `denyRead` にその絶対パスがある場合は、その設定を残す。
この判定は以下の追加・更新・削除より優先する。前二者は `existing-entry`、
後者は `denyread-conflict` で skip と表示する。
別の設定スコープとの競合や glob の包含関係は判定しない。

| ファイルの状態 | 設定と所有記録の扱い |
|---|---|
| 秘密を含み、ルールを生成できる | エントリを追加、または sumi 所有分を更新し、所有記録に載せる |
| 秘密を含むが生成できず、sumi 所有のエントリも無い | 登録しない |
| sumi 所有のファイルが無い、または読めた内容に秘密が無い | エントリと所有記録を削除する |
| sumi 所有のファイルに秘密があるが、ルールを生成できない | エントリと所有記録を削除し、終了コード1とする |
| ファイルや親ディレクトリを読めず、存在・内容を確認できない | エントリと所有記録を残し、終了コード1とする |
| root 外、または `.git`・secrets ファイル・シンボリックリンクとして除外したパス | エントリと所有記録を残す |

生成できなくなったルールを削除するのは、一部しか隠せない古いルールを登録済みのまま
残さないためである。削除後はファイルを平文で読めるので、`unmask` の表示と終了コード1で知らせる。
読み取り失敗は「ファイルが無い」「秘密が無い」と同じ扱いにしない。

sumi 所有のエントリを更新するときは、次の規則に従う。

| フィールド | 更新内容 |
|---|---|
| `path` | 同じ絶対パスを使う |
| `mode` | `mask` にする |
| `extract` | 生成した式に更新する。ファイル全体をマスクする場合は削除する |
| `maskDuplicates` | extract があれば `true` にする。無ければ削除する |
| `onExtractNoMatch` | `deny` にする |
| `injectHosts` とその他のフィールド | 利用者の設定を維持する。削除されているフィールドも補わない |

### 保存

設定と所有記録はそれぞれ元の内容と比較し、変更があるものだけを書く。
設定を変更し、原本が存在する場合は、`init` と同じ
`<設定パス>.bak.<YYYYmmddHHMMSS>`、mode 0600 のバックアップを取る。

走査で秘密を含むと確認したファイルが、今回変更する設定または所有記録と同じ実体なら、
固定診断と終了コード1で中止する。出力先の末尾シンボリックリンクとハードリンクも
実体の同一性で判定し、判定エラーを別ファイルの証拠にしない。バックアップ・ディレクトリ
の作成や保存より前に検証し、拒否時は既存の内容・名前・mtime を維持する。
変更しない出力と、秘密を含まない走査済みファイルにはこの制約を適用しない。

両方の出力を作り終えてから、設定、所有記録の順に保存する。
所有記録の保存に失敗したら設定を今回の原本に戻す。新規作成だった場合は削除する。
復元にも失敗したら、両方のパスと復旧が必要なことを報告する。
プロセスの強制終了をまたいで二つのファイルを同時に更新することまでは保証しない。

設定・所有記録に秘密や展開パターンを書き足してはならない。
バックアップは原本の複製なので、利用者が原本に書いていた値を含むことはある。

## 抽出ルールの生成規則

ファイルの内容をバイト列 C、秘密一覧から展開したパターンの集合を P とする。
P の各パターンが C に現れる区間を、重なりも含めてすべて集め、集合 O とする。
生成の成功条件は、O のすべての区間をマスクでき、かつ設定に秘密を書かないことである。

C の末尾から LF または CRLF を一つだけ除いた結果が P のいずれかと完全に等しければ、
ファイル全体をマスクする。それ以外では、次の手順で extract を生成する。

### 値を抽出できる箇所を探す

抽出候補は、行頭から値の直前までの「前置き」、値の形式、値の区間を持つ。
前置きにはインデント、キーより前の文字列、区切り、値の開き引用符も含める。
値の区間は O の少なくとも一つを完全に含むものとする。
キーや値をデコードせず、ファイルに書かれたバイト列を扱う。

候補を認識するための共通規則は次のとおり。

- 空白は SP / HT、行末は LF または CRLF とする。
- キーは `A-Z a-z 0-9 _ . - / :` が2文字以上続くものとする。
  同じ引用符で囲まれたキーも許す。引用符の内側は同じキー文字だけとする。
- キーの直前は、ファイル先頭、SP / HT / CR / LF、`{`、`,`、`;` のいずれかとする。
  引用符付きのキーでは、開き引用符の直前を調べる。
- 代入の区切りは `=` または `:` とし、前後に SP / HT を0個以上許す。

各出現を含む候補を、次の形式順で探す。

| 形式 | 例 | 抽出する範囲 |
|---|---|---|
| `dq` | `API_KEY="value"`、`"password": "value"` | 二重引用符の内側 |
| `sq` | `API_KEY='value'` | 一重引用符の内側 |
| `bare` | `api.token=value`、`token: value` | 区切り後の空白を除き、次の空白・改行・末尾まで |
| `ws` | `password value`、`Basic value` | キー後の空白を除き、次の空白・改行・末尾まで |

`dq` / `sq` は、同じ行に閉じ引用符があり、内部が空でなく、バックスラッシュと同種の
引用符を含まない場合に対応する。エスケープは解釈しない。異種の引用符や空白は許すので、
`PASSWORD='DecoyPass"7'` は `sq` に当たる。
`bare` / `ws` は値が空でなく、引用符で始まらない場合に対応する。
引用符付きで始まる値の認識に失敗しても、引用符なしとして取り直さない。

出現が代入の値に含まれる場合は、その候補を `ws` より優先する。
例えば `API_KEY="long secret"` の `secret` を、内側の `long secret` から抽出しない。
`Authorization: Basic value` の `value` は代入の最初の値 `Basic` に含まれないため、
`Basic value` を `ws` として扱える。`.netrc` の `password value` も同じ形式で扱う。

`DATABASE_URL=postgres://app:secret@db` では、URL 全体を `bare` の値として抽出する。
base64 の途中に秘密を含む代入も、その値全体を抽出する。
値の内部からキーを推定したり、URL のパスワード部分だけを抜き出したりはしない。
値全体が sentinel に置き換わるため、その値の構造を必要とする処理は動かなくなる場合がある。

### 同じ値には代表の箇所を使う

すべての候補を extract に列挙する必要はない。例えば次のファイルでは、
`foo` から `MY_SECRET` を抽出すれば、`maskDuplicates: true` により
`bar` とコメントも同じ sentinel に置き換わる。`bar` 用の前置きは生成しない。

```properties
foo=MY_SECRET
bar=MY_SECRET
# MY_SECRET
```

異なる値には、それぞれを抽出する箇所が必要になる。
次の例では `foo` と `bar` を使い、`copy` は使わない。

```properties
foo=FirstSecret9
bar=SecondSecret7
copy=FirstSecret9
```

平文と base64 など、文字列として異なる表現も別の値として扱う。
抽出できない箇所があっても、抽出した値のコピーとして隠せるなら登録できる。

代表は次の手順で選ぶ。

1. 候補を、値のバイト数が短い順、同じなら値の開始位置が早い順に並べる。
   同じ区間なら形式順、前置きの開始位置順で決める。
   短い値を優先するのは、周辺文字を余分に含まず、ほかの箇所のコピーにも使いやすいためである。
2. 選択済み候補を空にし、候補を一つ加えた extract を仮に生成する。
   次の二節の規則で、その式全体が隠せる O の区間を求める。
3. 隠せる区間が増え、これまで隠せた区間もすべて隠せる場合だけ採用する。
   既にコピーとして隠せる値の別キーや、同じ前置き・形式は追加しない。
4. O の全区間を隠せたら終了する。候補を使い切っても残れば `coverage` とする。

前置きに P のパターンを含む候補は、選択前に除外する。
エスケープで秘密が見えなくなるだけの設定も作らないよう、エスケープ前の前置きで調べる。
生成した正規表現の文字列にも P のパターンを含めてはならない。
候補が初めから無ければ `no-form`、秘密を含むためにすべて除外されたら
`prefix-contains-value` とする。

行頭からの前置きに別の秘密が含まれる候補も、同じ規則で除外する。
例えば同じ行に異なる秘密が二つあり、後の値を抽出する前置きに先の秘密が含まれるなら、
別の行などから後の値を抽出できる場合だけ登録できる。前置きに秘密を書いて通してはならない。

最短の正規表現を求めるための全組み合わせの探索や、完成後の最小化は行わない。

### 正規表現を組み立てる

前置きは、行頭から値の直前までをそのまま使う。例えば次の行では、
`machine h login u password ` が前置きになる。

```text
machine h login u password MY_SECRET
```

行頭から照合するため、キー直前の文字を調べる境界条件は生成しない。
前置きの空白も元の文字列どおりに照合し、空白の個数を許容する式へ展開しない。
正規表現の特殊文字 `\ ^ $ . | ? * + ( ) [ ] { } /` だけをエスケープする。

選択した前置きを `dq`、`sq`、`bare`、`ws` の順、同じ形式では元ファイルの
開始位置順に並べ、重複を除いて P1 … Pn とする。

行頭の指定には `(?:^|\n)` を使う。これはファイル先頭または LF の直後から
前置きを照合するためのもので、LF 自体は値のキャプチャに含めない。
`^` だけで各行に一致させるには `m` フラグが必要だが、Claude Code が使う
フラグは確認できていない（F5）。この形なら `m` が無くても2行目以降に一致する。

選択した候補に現れる形式から、値の選択肢 A1 … Am を次の順で作る。

| 形式 | 値の選択肢 |
|---|---|
| `dq` | `(?<=")[^"\\\r\n]+(?=")` |
| `sq` | `(?<=')[^'\\\r\n]+(?=')` |
| `bare` / `ws` | `(?<!["'])(?!["'])[^ \t\r\n]+` |

extract は `(?:^|\n)(?:P1|…|Pn)(A1|…|Am)` とする。
前置きが一つなら、前置きを囲む `(?:…)` は省く。
値の選択肢を囲む一組だけがキャプチャであり、グループ1になる。
引用符付きの値では閉じ引用符の存在を確認し、引用符自体は捕捉しない。

上の `.netrc` の行では、次の式になる。

```regex
(?:^|\n)machine h login u password ((?<!["'])(?!["'])[^ \t\r\n]+)
```

値の形式ごとの終端は維持する。引用符や、値の後に続く別の項目をマスクに巻き込まないため、
一律に `(.*)$` とはしない。

sumi の照合器は、この生成形だけを扱う。候補、正規表現、照合器の入力を共通の
中間表現から作り、生成した文字列を解析し直さない。
JavaScript の `g` フラグ付き正規表現と同様、最も左の一致を取り、一致全体の末尾から
次を探す。選択肢は左から試し、量指定子は貪欲に扱う。

### すべての秘密を隠せるか確認する

照合器で extract を C に適用し、一致全体の区間 H と、グループ1の区間 G を求める。
続いて、G で捕捉した文字列全体のコピーを C 内から探す。
H の外にあり、他のコピー候補とも重ならない出現を D とする。
重なるコピー候補は、どちらも D に数えない。

O の各区間が、G または D の一つの区間に完全に含まれれば、その秘密は隠せる。
すべての区間でこの条件を満たすことを、代表の選択中と、完成した式の両方で確認する。

コピーの検索には捕捉した文字列全体を使う。秘密一覧の値で代用しない。
例えば `abMY_SECRETab` を捕捉しても、単独の `MY_SECRET` はそのコピーではない。
単独の値が別に残るなら `coverage` になる。

D の数え方は、未検証の重なりや一致境界の挙動に頼って登録を成功させないためのものとする。
Claude Code が別キーとコメントの単純なコピーを置き換えることは実験済みだが（F16）、
この生成規則で数える範囲が実際に置き換わることは、実装時のホスト試験でも確認する。

抽出ルールを使うエントリには、コピーの有無によらず `maskDuplicates: true` を書く。
同じ値を隠す方法を一つに揃え、現在コピーがある場合だけ別の生成処理に切り替えない。
短い値や一般的な値では、同じファイルの別の部分も置き換わり得る（F14）。
この性質は README に記載し、scan 独自のエントロピー閾値は導入しない。

## 表示と終了コード

表示先は stderr とし、ファイルごとに次の形式で結果を出す。

| 結果 | 表示 |
|---|---|
| 新規登録・更新 | `mask <path>` |
| 登録を見送った | `skip <path>: <理由コード>` |
| ファイルが無い、または秘密が無いため削除 | `unmask <path>` |
| 生成不能になった既存ルールを削除 | `unmask <path>: was masked, now <理由コード>` |

最後に `N masked, N unmasked, N skipped in <settings>` を出す。
理由コードは `glob-chars`、`too-large`、`not-utf8`、`no-form`、
`prefix-contains-value`、`coverage`、`existing-entry`、`denyread-conflict` とする。
読み取り失敗は警告として表示する。
値・キー・extract・前置きは表示せず、パス、理由コード、件数、固定の案内文に限る。

`sumi: note:` の案内は、書き込み後の設定に合わせる。

- `sandbox.enabled` が `true` でなければ、別スコープで有効化が必要なことを知らせる。
- `injectHosts` が空なら、送信時にも本物へ戻らないことと、Claude Code の起動時に
  empty injectHosts の警告が出ることを知らせる（F15）。
- 利用者が送信先を設定済みなら、「本物は送られない」と案内しない。
- scan が確認できるのは、この書き込み先の設定だけであることを知らせる。

| 結果 | 終了コード |
|---|---|
| 正常終了。新規ファイルの skip を含む | 0 |
| 読み取り・設定検証・保存の失敗、書き込み先の拒否、生成不能な既存ルールの削除 | 1 |
| 引数の誤り | 2 |

## 実装範囲と受け入れ条件

`contrib/sumi/claude/scan.zig` を更新し、抽出候補の認識、代表の選択、正規表現の生成、
マスク範囲の確認を `claude/extract.zig` に置く。
`tests/run-tests.sh` の scan 試験を更新し、`tests/extract-parity.ts` で
JavaScript の正規表現との一致を検証する。
README と CHANGELOG には、新しい scan の使い方、設定先、送信先の設定、再走査が
必要なこと、値全体やコピーも置き換わることを反映する。

### コマンドと設定反映

ブラックボックステストでは、一時ディレクトリとデコイ値を使って `sumi scan` を実行し、
設定・所有記録・表示・終了コードを確認する。

- 新規追加、sumi 所有分の再生成、不要になったエントリの削除。
- 利用者のエントリ、同一 path の複数エントリ、denyRead との競合時に設定を維持する。
- root 外や走査から除外したパス、読み取り不能で確認できないパスの設定を維持する。
- extract ありとファイル全体の相互変更で、extract と maskDuplicates を追加・削除する。
- 既存の maskDuplicates が false または未指定でも、抽出ルールの再生成では true にする。
- 利用者の injectHosts とその他のフィールドを維持し、その状態に合った note を出す。
- 生成不能になった既存ルールを削除し、終了コード1を返す。
- 不正な設定・所有記録やプロジェクト `.claude` への書き込み先指定では、何も書かない。
- 保存失敗時には設定を復元し、復元の失敗も報告する。
- 同じ内容で再実行したときは、設定・所有記録・バックアップを書かない。
- 新規に生成する設定・所有記録と表示に、デコイ値やその展開パターンを含めない。

### 抽出ルール

以下の X / Y は4バイト以上の具体的なデコイ値に置き換える。
キーは例示どおり2文字以上を使う。

| 入力 | 確認する結果 |
|---|---|
| `db.password=X` | 値を捕捉し、`maskDuplicates: true` を付ける |
| `foo=X`、`bar=X`、`# X` | `foo` だけを選び、3箇所を隠す |
| `foo=X`、`bar X Y`、`# X`（保護対象は X のみ） | `bar X` は ws 候補になるが選ばず、`foo` だけで隠す |
| `foo=X`、`bar=Y`、`copy=X`（X と Y は同じ長さの異なる値） | `foo` と `bar` を選び、`copy` は選ばない |
| `foo=X`、`bar="X"`、`baz='X'` | 最初の `foo` を選び、コピーも隠す |
| `API_KEY="DecoyToken9"`、`PASSWORD='DecoyPass"7'` | dq と sq の両方を選び、引用符を残す |
| `{"user":"app","password":"X"}` | password の値だけを捕捉し、JSON を保つ |
| `.npmrc` の `//registry.npmjs.org/:_authToken=X` | bare として捕捉する |
| `.netrc` の `machine h login u password X` | 行頭から `machine h login u password ` を照合し、X を捕捉する |
| `Authorization: Basic <base64(user:X)>` | Basic の後の文字列全体を捕捉する |
| `DATABASE_URL=postgres://app:X@db` | URL 全体を捕捉する |
| `encoded=<X を内部に含む base64>` | base64 全体を捕捉する |
| `foo=X` と、抽出形式に当たらない箇所の base64(X) | その表現を隠せないため coverage になる |
| `foo=abXab` と単独の `# X` | 単独 X はコピーではないため coverage になる |
| 値だけのファイル、末尾改行あり／なし | extract と maskDuplicates を省略する |
| 候補なし／秘密を含む前置きしかない | no-form / prefix-contains-value になる |

LF / CRLF の2行目以降、インデント付きの行でも、行頭からの前置きで値を捕捉する。
前置きより前に別の文字がある行には一致しない。
同じ行の前置きに別の秘密を含む候補は除外し、ほかの代表で隠せなければ登録しない。

閉じ引用符が無い値と、引用符付きの値内にエスケープがある場合は候補にせず、
bare に取り直さない。コピー同士や一致全体と重なる出現を D に数えないことも確認する。

### 照合器と実際のマスク結果

`zig build test` で候補の認識、代表の選択、照合器、設定反映を検証する。
`tests/extract-parity.ts` では、生成した式を `new RegExp(extract, "g")` に通し、
一致全体とグループ1の区間が照合器と一致することを確認する。
同じ式を `gm` でも実行し、LF / CRLF のファイルで捕捉する値が変わらないことも確認する。
JavaScript の位置は UTF-16 単位なので、UTF-8 のバイト位置に変換して比較する。
G と D の区間を置換した結果に P が残らないことも確認する。

Bun は開発・CI の検証だけに使い、製品の実行時には必要としない。
Bun が無い手動テスト環境では skip と表示し、Bun がある CI では必ず実行する。

ホスト試験では、scan が実際に生成したルールで `app.properties`、同じ値の別キーと
コメント、dq / sq 混在、JSON、異なる秘密を含むファイルをマスクする。
`cat` と `od` で読み、秘密が出ず、値以外の設定部分と引用符が残ることを確認する。

既存の実験で確認できているのは、単純な extract と別キー・コメントのコピーである。
行頭からの照合、引用符の確認、複数候補の合成は未確認なので、生成した式で検証する。
コピーの部分文字列や一致境界付近も対照試験を行い、D として数えた範囲が実際に
置き換わることを確認する。結果が異なれば、その生成規則を見直す。
照合器のテストだけで、Claude Code のマスク結果を確認済みとはしない。
