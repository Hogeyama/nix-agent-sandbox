---
title: ホストの DB・API への接続
description: ホストの localhost サービスをコンテナから使うための転送設定
---

ホストで動いている DB や API をエージェントから使う場合は、必要なポートだけを転送します。ホストのサービスを 0.0.0.0 で待ち受けさせる必要はありません。

転送の追加には二つの方法があります。作業中のセッションに今すぐ足すなら UI の **Ports · out** か `nas network forward` を使い、毎回のセッションで最初から使えるようにするならプロファイルに書きます。

エージェントが作ったサーバーをホストのブラウザで見たい場合は逆方向なので、[開発サーバーの確認](/nix-agent-sandbox/work/preview/)を使います。

## 転送するサービス

**この転送に HTTP の通信ルールや承認は適用されません。** 転送先が認証のない DB や管理 API なら、エージェントもそのまま操作できます。必要なサービスだけを選び、サービス側の認証・権限も設定してください。

nas UI 自身のポートを転送すると、エージェントが承認 API に到達できるようになります。転送しないでください。

## 作業中のセッションに追加する

UI の **Sessions** で作業を選び、右の **Pending** 内にある **Ports · out** の **Host port** にホスト側のポート番号を入力して **Forward** を押します。コンテナ内では同じ番号の `localhost:<port>` で接続できます。ホスト側のサービスがまだ起動していなければその旨が表示されますが、転送は保持されるので、あとからサービスを起動しても接続できます。

CLI からは次のように追加します。

```bash
nas network forward <session-id>:5432          # コンテナ内 localhost:5432 → ホスト 127.0.0.1:5432
nas network forward <session-id>:5432 15432    # コンテナ内 localhost:5432 → ホスト 127.0.0.1:15432
nas network forward <session-id>               # ホストで待ち受け中のポートから fzf で選ぶ
nas network forward                            # 開いている転送を一覧表示
```

`<session-id>:<port>` の `<port>` はコンテナ側の番号で、[開発サーバーの確認](/nix-agent-sandbox/work/preview/)の `bind` と同じ書き方です。ホスト側の番号を省略すると同じ番号になります。

転送はコンテナが起動しているときだけ追加できます。コンテナ内でその番号を別のプロセスが使っている場合、または内部プロキシの 18080 などの nas が使う番号の場合は失敗します。

解除は **Ports · out** の **Unforward**、または `nas network unforward <session-id>:<port>` です。セッションが終了すると転送も閉じます。

## プロファイルで固定する

ホストの 127.0.0.1:5432 と 127.0.0.1:8080 を使う例です。[対象プロファイル](/nix-agent-sandbox/configuration/profiles/#プロファイルの編集)に追加します。

```pkl
network {
  proxy {
    forwardPorts { 5432; 8080 }
  }
}
```

forwardPorts は既定で空です。重複したポートと、内部プロキシ用の予約番号 18080 は指定できません。

## 接続の確認

設定を確認して再信頼し、新しいセッションを起動します。コンテナ内から、5432 のサービスには `localhost:5432`、8080 のサービスには `localhost:8080` で接続します。同じ番号でホストの 127.0.0.1 へ中継されます。

接続できない場合は、ホスト側のサービスがそのアドレスで動いているか、サービス側の認証情報が正しいかを確認します。

不要になったポートは設定から削除し、新しいセッションへ反映します。プロファイルで固定した転送は **Ports · out** には表示されず、**Unforward** でも解除できません。UI の Ports · in の Unbind は逆方向の公開解除なので、この転送の解除には使いません。
