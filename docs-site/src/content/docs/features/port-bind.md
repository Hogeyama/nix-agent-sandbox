---
title: コンテナポート公開
description: ホストからコンテナの開発サーバーへの接続
---

コンテナで起動した開発サーバーをホストのブラウザで開くには、`nas network bind` を使います。プロファイルの変更やセッションの再起動は不要です。接続先はホストの `127.0.0.1` に公開され、LAN には公開されません。

ホストのサービスをコンテナから使う場合は、逆方向の[localhost ポート転送](/nix-agent-sandbox/features/port-forwarding/)を設定します。

## CLI 操作

まずホストで次のコマンドを実行し、対象のエージェントコンテナ名とセッション ID を確認します。

```sh
docker ps --filter label=nas.session_id --format '{{.Names}}\t{{.Label "nas.session_id"}}'
```

以下の `<session-id>` を表示された ID に置き換え、ホストでコンテナポートを明示して開きます。ホストポートを省略すると、最初に同じ番号を試し、使用中なら近くの空きポートを選びます。

```sh
nas network bind <session-id>:3000
nas network bind <session-id>:3000 8080
```

成功時に表示される URL をホストのブラウザで開きます。ホストポートを `8080` にした場合は `http://localhost:8080` です。

指定したセッションで未公開の待ち受けポートを検出し、`fzf` で選ぶこともできます。nas 自身のポートと、カーネルの一時ポート範囲は候補から除外されます。

```sh
nas network bind <session-id>
```

接続先はコンテナ内の `127.0.0.1` です。サーバーは `0.0.0.0` または IPv4 ループバックで待ち受けてください。他のアドレスや IPv6 だけで待ち受ける場合は接続できません。

現在の公開ポートは引数なしで一覧にできます。機械処理では JSON を選べます。

```sh
nas network bind
nas network bind --format json
```

閉じるときはセッションとコンテナポート、またはホストポートを指定します。引数を省略すると `fzf` で選びます。

```sh
nas network unbind <session-id>:3000
nas network unbind 8080
nas network unbind
```

明示したホストポートが使用中または権限不足の場合は、別のポートへ自動変更せずエラーになります。接続確認に応答がなくても公開ポートは作成され、CLI に警告が表示されます。

## UI 操作

ブラウザ UI ではセッションを選び、`Ports · in` パネルを使います。コンテナで検出した待ち受けポートの `Bind`、ポート番号の直接入力、公開 URL のリンク、既存ポートの `Unbind` を一か所で操作できます。CLI の変更は UI にも反映されます。

## 終了時の動作

セッションまたは起動元の nas プロセスが終了すると、公開ポートも閉じます。異常終了後に登録情報だけが残った場合は `nas network gc` で削除できます。

ポート公開機能に未対応の古い nas で開始したセッションや、通信の仲介プロセスが終了したセッションには公開設定を追加できません。セッションを再起動してください。

## 注意点

公開先はホストの `127.0.0.1` ですが、ページの内容はエージェントが制御します。そのページをブラウザで開くと、同じホストの別のローカルサービスへ要求を送る場合があります。ブラウザが応答の読み取りを禁止しても、送信自体は防げません。認証なしの管理 API などを併用する場合は注意してください。

公開と解除はホスト側の操作で、通信の承認キューは使いません。コンテナからこのコマンドを呼ぶ場合は、別途 HostExec のルールと承認が必要です。
