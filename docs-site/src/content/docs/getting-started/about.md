title: nas とは
description: nas が隔離するものと、必要な権限だけを有効にする考え方

nas は Claude Code、GitHub Copilot CLI、OpenAI Codex CLI を Docker サンドボックスで起動するための CLI です。作業ワークスペースはエージェントへ読み書き可能にマウントされます（プロジェクトの `.nas/config.pkl` は読み取り専用で保護されます）。さらに存在する場合、選択したエージェントのホスト設定・認証ディレクトリ（`~/.claude`、`~/.codex`、または旧 `~/.copilot`。Claude では `~/.claude.json` も）は読み書き可能でマウントされ、`~/.config/git` は読み取り専用でマウントされます。それ以外のワークスペース外のホストファイルシステムと外部ネットワークは、起動時には利用できません。

## 必要なものだけを有効にする

プロジェクトごとの profile に、エージェントが必要とする機能を追加します。たとえば追加のホストパスのマウント、指定したネットワーク接続、Docker in Docker、Worktree は明示的な設定が必要です。Nix 統合は例外で、既定の `nix.enable = "auto"` によりホストで Nix が検出されると有効になり、既定の `mountSocket = true` により `/nix` がマウントされます。設定で穴を開ける前に、そのエージェントとプロジェクトに本当に必要かを確認してください。

nas は、秘密をコンテナへそのまま渡さずにホストで必要なコマンドだけを実行する HostExec や、プロジェクト設定の信頼確認も提供します。これらも隔離を完全に保証するものではなく、許可する機能ごとに信頼境界が変わります。

Nix の条件付き既定値を含む各 capability の到達先とリスクは、[機能別リスク](/nix-agent-sandbox/security/risks/#nix-socket)で確認してください。

まずは [インストール](../installation/) と [クイックスタート](../quick-start/) で、生成される最小設定から始めてください。
