---
title: 開発サーバーの確認
description: エージェントが起動した開発サーバーの確認と、確認後の公開解除
---

エージェントが起動した開発サーバーは、UI の **Ports · in** から公開してホストのブラウザで確認できます。作業中のセッションに追加でき、設定の書き換えや再起動は不要です。

## 公開対象のサーバー

エージェントに開発サーバーを起動させます。中継先はコンテナ内の `127.0.0.1` なので、サーバーは IPv4 の `127.0.0.1` または `0.0.0.0` で待ち受ける必要があります。

UI の **Sessions** でその作業を選び、右の **Pending** 内にある **Ports · in** を確認します。ペインが閉じていれば展開してください。

## ポートの公開

**Detected in container** に、コンテナ内で検出した待ち受けポートが表示されます。確認したいサーバーのポートの **Bind** を押します。候補にない場合は、サーバーの起動ログなどでポート番号を確認し、**Container port** に入力して **Bind** を押します。

## ブラウザでの確認

公開済み一覧の **localhost:…** リンクを開きます。ホスト側で同じポート番号が使用中なら、別の空きポートが選ばれます。コンテナ内の番号から URL を推測せず、表示されたリンクを使ってください。

公開先はホストの `127.0.0.1` で、LAN には公開されません。ただし、開くページの内容はエージェントが制御します。そこから他のローカルサービスへ要求を送信する可能性もあるため、認証のない管理 API などを同時に使う場合は[公開時のリスク](/nix-agent-sandbox/security/isolation/#通信とホストへの経路)を確認してください。

ページが表示されたら、エージェントに依頼した変更を確認します。表示の問題は、コンテナ内でサーバーがまだ動いているか、ポート番号が合っているかを確認してください。公開が成功しても、サーバー自体の動作は保証されません。

## 確認後の公開解除

公開済み一覧の **Unbind** を押し、その行が消えたことを確認します。ホストからの転送は終了しますが、コンテナ内のサーバーは動き続けます。サーバー自体も不要なら、エージェントに停止させてください。

セッションが終了すると公開ポートも閉じます。

## 候補や接続の問題

**not on 127.0.0.1** と表示される候補は、待ち受けアドレスを確認します。IPv6 だけ、または別のアドレスで待ち受けるサーバーには、この転送では接続できません。

古い nas で開始したセッションや、通信の仲介プロセスが終了したセッションには公開設定を追加できません。エージェントの作業を確認してからセッションを起動し直します。異常終了後の登録情報が残っている場合は、ホストの `nas network gc` で回収できます。

ホストの DB や API をエージェントから使いたい場合は、転送方向が逆です。同じペインの **Ports · out** から追加できます。[ホストの DB・API への接続](/nix-agent-sandbox/configuration/host-services/)を参照してください。
