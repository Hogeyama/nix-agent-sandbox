---
title: 開発サーバーの確認
description: コンテナの開発サーバーを Local 転送でホストのブラウザに開く
---

エージェントが起動した開発サーバーは、Local 転送を追加してホストのブラウザで確認できます。作業中のセッションへ追加でき、設定の書き換えや再起動は不要です。

## コンテナのサーバーを起動する

エージェントに開発サーバーを起動させます。転送先はコンテナ内の `127.0.0.1` なので、サーバーは IPv4 の `127.0.0.1` または `0.0.0.0` で待ち受ける必要があります。起動ログなどでコンテナ側の番号を確認します。ここでは 3000 とします。

## Local 転送を追加する

UI の **Sessions** でその作業を選び、右の **Pending** にある **Ports** を確認します。ペインが閉じていれば展開してください。

**Detected in container** に `:3000` が表示された場合は、その行の **Add** を押します。候補にない場合は **Direction** で **Local (host → container)** を選び、**Container port** に `3000` を入力して **Add forward** を押します。**Host port** を空欄にすると利用可能な番号が選ばれます。8080 を使う場合は、両方を入力します。

<img src="/nix-agent-sandbox/images/ui-port-bind.png" width="340" alt="Local と Remote の転送一覧、内部用途との共有、検出した候補、方向と両ポートの入力欄" />

例示用データの画面です。Local の行だけにホスト向けリンクがあり、内部用途との共有を含む行には **Remove user** が表示されます。

CLI では、左にホスト側の待受番号、右にコンテナ側の接続先番号を指定します。

```bash
nas network bind <session-id> -L 8080:3000
```

## ブラウザで確認する

一覧に **Local** と `host localhost:8080 → container localhost:3000` が表示されます。Local の `host localhost:8080` リンクを開きます。自動で番号を選んだ場合は、コンテナ内の番号から URL を推測せず、表示されたリンクを使ってください。Remote の行にはホスト向けリンクがありません。

公開先はホストの `127.0.0.1` で、LAN には公開されません。ただし、開くページの内容はエージェントが制御します。そこから他のローカルサービスへ要求を送信する可能性もあるため、認証のない管理 API などを同時に使う場合は[公開時のリスク](/nix-agent-sandbox/security/isolation/#通信とホストへの経路)を確認してください。

ページが表示されたら、エージェントに依頼した変更を確認します。Local 転送が active でも、コンテナ側のサーバーが停止していればページは表示されません。

## 確認後に解除する

一覧の **Remove** を押し、その行が消えたことを確認します。CLI ではホスト側の待受番号を指定します。

```bash
nas network unbind <session-id> -L 8080
```

ホストからの転送は終了しますが、コンテナ内のサーバーは動き続けます。サーバー自体も不要なら、エージェントに停止させてください。セッションが終了すると転送も閉じます。

毎回同じ転送を使う場合は、[対象プロファイル](/nix-agent-sandbox/configuration/profiles/#プロファイルの編集)に追加します。

```pkl
network {
  localForwards {
    new PortForwardConfig { hostPort = 8080; containerPort = 3000 }
  }
}
```

設定を確認して `nas config trust` を実行し、変更したプロファイルで新しいセッションを起動すると、最初から一覧に表示されます。設定由来の行も現在のセッションでは Remove できますが、次の新しいセッションでは設定が再び適用されます。

## 候補や接続の問題

**not on 127.0.0.1** と表示される候補は、待ち受けアドレスを確認します。IPv6 だけ、または別のアドレスで待ち受けるサーバーには、この転送では接続できません。

古い nas で開始したセッションや、通信の仲介プロセスが終了したセッションには転送を追加できません。エージェントの作業を確認してからセッションを起動し直します。異常終了後の登録情報が残っている場合は、ホストの `nas network gc` で回収できます。

ホストの DB や API をエージェントから使いたい場合は、同じ **Ports** で Remote を選びます。[ホストの DB・API への接続](/nix-agent-sandbox/configuration/host-services/)を参照してください。
