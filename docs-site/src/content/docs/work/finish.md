---
title: 作業の終了と片付け
description: 変更の保存、セッションの終了、worktree・補助コンテナ・残存データの削除
---

エージェントを止める前に、残したい変更がどこにあるかを確認します。ブラウザを閉じる操作、ターミナルの切り離し、セッションの終了、作業フォルダーの削除は、それぞれ異なります。

## 保存対象の変更

| 作業場所 | 残るものと確認事項 |
| --- | --- |
| 通常のプロジェクト | 共有ファイルへの変更はホストに残る。差分を確認して必要な変更を保存する。 |
| nas が作成した worktree | その worktree とブランチに変更がある。元のブランチに自動で入るとは限らない。 |
| コンテナ内だけのファイル | セッション終了後には残らない。必要なら終了前に共有フォルダーへ保存する。 |

## セッションの終了

作業を終えるときは、エージェントの終了操作を使います。UI から停止する場合は、Sessions で対象を確認し、ターミナルのツールバーの **Stop container** を押します。実行中の処理を中断する操作なので、結果を待つ必要がないか確認してください。

ブラウザを閉じるだけではエージェントは終了しません。後で続きを行うために切り離す場合は、[再接続可能なセッション](/nix-agent-sandbox/work/sessions/#エージェントへの入力と再接続)として起動しておきます。

セッションが終了すると、そのセッションの公開ポートも閉じます。UI はセッションも承認待ちもなくなると、既定で300秒後に自動停止します。UI の停止だけではエージェントの終了にはなりません。

## Worktree の保存と統合

nas が新しく作った worktree では、エージェント終了後に保存か削除の選択が出ます。CLI から起動した場合は起動元のターミナル、UI の + new session から起動した場合は中央のブラウザターミナルで回答します。**Stop container を押した場合も、ブラウザを閉じる前に終了後の選択を確認してください。**

変更を後で確認・統合する場合は、`What to do with the worktree?` に **2（Keep）**を入力し、`Worktree kept: <パス>` を確認します。worktree、ブランチ、未コミットの変更をそのまま残す操作で、自動コミットや stash はしません。既存の worktree を再利用して起動した場合は、この質問なしでそのまま残ります。

保存した変更を元のブランチへ取り込む場合は、ホストで保存先へ移動し、`git status` と `git diff` で内容を確認してコミットします。元の作業フォルダーへ戻り、取り込み先ブランチの差分を確認してから、保存したブランチを `git merge <ブランチ名>` などで統合します。作業フォルダーとブランチ名は `nas worktree list` で確認できます。

### 終了時の削除とブランチ処理

最初の質問で **1（Delete）**を選ぶと削除へ進みます。未コミットの変更がある場合は、stash して削除、stash せず削除、保存の選択が出ます。stash は未追跡ファイルを含みますが、Git の無視対象ファイルは含みません。必要なデータが不明なら Keep を選んでください。

削除を続け、そのブランチに固有のコミットがある場合は、ブランチの削除、基準ブランチへの cherry-pick、名前を変えてブランチを保存、の選択が出ます。**名前変更で残るのはブランチで、worktree は削除されます。** cherry-pick に失敗した場合もブランチは残りますが、worktree は削除されるため、ホストで Git の状態を確認します。

### 未使用 Worktree の一括削除

まずホストで対象を確認します。

```sh
nas worktree list
nas worktree list --format json
```

対象はディレクトリ名が `nas-` で始まる Git worktree です。手動で作った同名形式の worktree も含まれます。

**必要な変更を保存し、使用中のエージェントとコンテナを終了してから削除します。** この削除は使用中の worktree も対象にし、未コミットの変更も失います。`nas session list` は dtach のセッションだけなので、一覧が空でもすべて停止した証拠にはなりません。UI の Sessions でも作業を確認してください。

```sh
nas worktree clean
```

ブランチは既定で残ります。`--delete-branch`（`-B`）を付けると、削除した worktree のブランチに加え、開始時点で worktree に属していないすべての `nas/*` ブランチも削除します。確認を省略する `--force`（`-f`）は、対象と失う変更を確認済みの場合に使います。

## 未使用の補助コンテナ

UI の **Settings → Sidecars** では、dind、proxy、registry-mirror の状態を確認できます。停止操作はその補助サービスに影響するため、使用しているセッションを確認してください。

終了後に不要なコンテナなどを回収する場合は、ホストで一覧を確認してから実行します。

```sh
nas container list
nas container clean
```

`clean` は未使用の補助コンテナ、空のネットワーク、セッション用の一時ボリュームを削除します。実行中のエージェントと、それが使う補助コンテナは削除しません。公開 Docker Hub の取得キャッシュ `nas-registry-cache` は保持します。この使用中の判定は `worktree clean` にはありません。

## 異常終了後のデータ

通常の終了処理は補助プロセスや一時データの削除を試みますが、SIGKILL や削除失敗では残る場合があります。

通信のセッション登録情報、承認待ちディレクトリ、仲介プロセスのソケットが残っている場合は、ホストの `nas network gc` で回収できます。稼働中の通信状態は削除しません。

### 出力マスク用の秘密値

出力マスク用のセッションディレクトリには、権限 `0600` の `mask-secrets` ファイルに秘密値が平文で残る場合があります。**nas の再起動や `nas network gc` では自動回収されません。**

保存先は起動時の `$XDG_RUNTIME_DIR/nas/mask-filter/<session-id>/mask-secrets`、`XDG_RUNTIME_DIR` が未設定なら `/tmp/nas-<ホストのUID>/mask-filter/<session-id>/mask-secrets` です。ホストの UID は `id -u` で確認できます。使用中のセッションがないことを確認してから、該当セッションのディレクトリをホストで削除してください。

会話履歴や監査ログは、セッション用一時データとは別に残ります。削除方針は[記録と保存期間](/nix-agent-sandbox/configuration/recording/)で確認します。
