# ページの編集設計

対象は `src/content/docs/` の全30ページ。読者は通常の開発作業を知っているが、nas の仕組みや設定名は知らない。下表の前提を満たす読者が、そのページだけで何を決める・終えるかを示す。

文章の短縮ではなく、判断に必要な情報の選択と順序を管理する。読者が変わった場合はこの設計も更新する。既存原稿の内容から目的を後付けしない。

## トップ

対象: `index.mdx`

- 現在地：AI エージェントで開発している、または試したい。nas を導入するかは未定。
- 目的：自分の困りごとに役立ち、試す手間に見合うか判断する。
- 必要な答え：どんな作業・困りごと向けか → 何を任せられ何を制限できるか → 自分の環境で使えるか・設定作業は何か → 試す手順。
- 採用する事実：ソースの編集と秘密ファイルの非公開を分けられる。通信先を限定できる。認証が必要な作業へ秘密値を渡せる。Linux と Docker、対応エージェント、初期設定と通信設定が必要。
- 不採用：共有ディレクトリの詳細と変更の永続性（ファイル隔離・マウント、隔離の範囲）、ソケットやプロキシの構成（隔離の範囲）、Pkl のキーや HostExec という機能名による説明（機能別手順）、全機能への索引（サイドバー）。
- 書き方：困りごとは製品の仕組みを知らない読者も言える文。解決は作業の変化。機能名を用途の列に並べない。強い安全保証は書かない。

## 個別の設定例

共通前提：該当する問題を抱えており、設定の編集先を探している。エージェントとの通信を設定済みのプロファイルへの追加例とし、通信設定を消さない。例の目的、必要条件、設定位置、実行と結果を一続きにする。

| 対象 | 読了後の判断・作業 | 必要な答えの順序 | 別ページの情報 |
| --- | --- | --- | --- |
| `recipes/mask-env.md` | .env を隠し、必要なビルドだけに値を渡す | 対象作業 → 変更させてはいけない入力 → 完成例 → 再信頼・ルール確認・起動 → 出力マスク | HostExec の内部通信は不要。 |
| `recipes/relative-hostexec.md` | 相対パスのスクリプトの要求を一回限りで確認 | 固定できない実行元 → 前提 → 例と呼び出し → 承認前の実行元・変更確認 | 一般の承認一覧は approvals。 |
